# Cloudflare deployment of the NorthLedger site (prepared 6 Oct 2026, NOT live)

Nothing in this folder or in `wrangler.jsonc`, `deploy.sh` or `tools/*dist*` has been run against Cloudflare.
The launch is gated on the owner's in-the-moment "ship it"; the ordered steps are in
`../plan/CLOUDFLARE-LAUNCH.md` (data-analytics-portfolio/plan). This file says how the pieces fit.

## What is where

| File | What it is |
|---|---|
| `wrangler.jsonc` | Workers Static Assets config: `assets.directory = ./dist`, `not_found_handling = 404-page`, no routes yet |
| `deploy/cloudflare.config.json` | the deployment's own values: the new address, the old addresses kept as aliases, the runtime mode, header switches. The AI proxy address is NOT here: it is `site.config.json` `ai_proxy_url` |
| `deploy/_headers.tmpl`, `deploy/404.html` | templates that `tools/make_dist.py` fills in |
| `deploy/pyodide-pins.json` | Pyodide 0.27.7: every served file's size and sha256, the official lock's sha256, the six-package lock derived from it, the folder tag. No binaries in git |
| `deploy/gh-pages-stub/` | `index.html` and `404.html` for the old github.io address: a redirect to the new host keeping path, query and hash. Generated by `make_dist.py --stub`; the local branch `cf-gh-pages-stub` holds it as an orphan commit, not pushed |
| `tools/make_dist.py` | builds `dist/` from the BUILT site (needs no sibling repository, does not run `build.py`) |
| `tools/fetch_pyodide.py` | downloads the pinned runtime into `.cache/` and refuses any byte that is not the pinned one |
| `tools/check_dist.py` | lints `dist/`: sizes, dev files, links, runtime hashes, origins, `_redirects`, `_headers` and every CSP. No browser |
| `tools/serve_dist.mjs` | a local stand-in for Static Assets that applies `dist/_headers` and `dist/_redirects` |
| `tools/check_dist_csp.mjs` | the Playwright proof of the CSP on the real `dist/` (the whole demo, zero violations, zero outside requests) |
| `tools/test_dist_tools.py` | mutation tests: the linter must fail on every deliberately broken `dist/` |
| `tools/check_live_headers.py` | after a deploy: asks the REAL host (preview or domain) the same questions as `check_dist.py` and compares the answers, checks redirects, the 404 and that the page bytes arrive unchanged; prints the INFO lines that settle the plan's open items. Read-only |
| `tools/dns_snapshot.sh` | read-only DNS answers for the halosyncs.com names that must not change; run before and after the domain is attached and diff |
| `tools/measure_first_load.sh` | wire bytes and TTFB per host, for the before/after numbers |
| `deploy.sh` | the only deploy path; refuses without `--i-have-the-owners-go` and every gate |

## What the build does to the page (dist only, never the source)

`make_dist.py` copies the built files and makes five exact-text rewrites, each asserted (if the wording in
`index.html` or `engine/worker.js` changes, the build stops and says which sentence):

1. `engine/worker.js`: `PYODIDE_URL` becomes `new URL('pyodide/<tag>/', self.location.href).href`, this site's own
   copy; the comment above it is reworded.
2. `index.html`: the two sentences that said Pyodide comes from `cdn.jsdelivr.net` say "this site"; the error
   text for a failed runtime download likewise.

`runtime.mode = "jsdelivr"` in the config switches all of this off (and the engine worker's CSP then allows
that one origin).

## The headers

`_headers` is generated from `deploy/_headers.tmpl`. Cloudflare JOINS the same header set by several matching
blocks, so security headers live only in `/*` and the CSP and Cache-Control only in specific blocks; the linter
resolves every served path the way Cloudflare does and requires each protection exactly once.
The engine worker has a CSP of its own (`connect-src 'self'`): a worker takes the policy of its own response,
so it cannot reach the AI proxy or anything else. The page may connect to itself and the proxy.

## Commands

```bash
python3 tools/make_dist.py                      # build dist/ (fetches and verifies Pyodide; about 33 MB)
python3 tools/check_dist.py --js-crosscheck     # lint it (no browser)
python3 tools/test_dist_tools.py                # prove the linter bites
node tools/check_dist_csp.mjs dist --no-browser # server-side half of the CSP proof
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright node tools/check_dist_csp.mjs dist   # the browser half
PLAYWRIGHT_MODULE=... ./deploy.sh --dry-run     # every gate, then wrangler's dry run; deploys nothing
```
