Take it into Power BI

Your audited data arrives as a Power BI project, not only a PDF

The engine's export writes a Power BI Project (PBIP): the semantic model in TMDL text files, a report shell and the cleaned data as CSV. Here it is for the RentSafeTO evaluation view: {{d pbip_tables}} tables, {{d pbip_measures}} engine-generated measures, {{d pbip_rels}} relationship, {{d pbip_files}} files.

What it holds, and what it does not: every current-method evaluation, one row each ({{d pbip_rows}} rows, {{d pbip_first}} to {{d pbip_last}}, every evaluation cycle), not the report's latest evaluation per building ({{f rentsafe_meta:kpis.buildings|int}} buildings). So its averages differ from the cards above: its mean current score is {{d pbip_mean}}, against a simple mean of {{f rentsafe_meta:kpis.score_mean|fixed:1}} in the report. It has no building key and no unit count, so the report's latest-per-building view and its unit-weighted score cannot be rebuilt from it yet.

Status, at exactly the level reached: structure checked on a Mac with pbip_lint ({{f engine_scorecard:rentsafe.cli_run.exports.view-2023.pbip_lint}}); the TMDL loaded by Microsoft's own parser ({{f engine_scorecard:rentsafe.cli_run.exports.view-2023.tmdl_tool}}: {{f engine_scorecard:rentsafe.cli_run.exports.view-2023.tmdl_tables|int}} tables, {{f engine_scorecard:rentsafe.cli_run.exports.view-2023.tmdl_relationships|int}} relationship); DAX and Power Query not evaluated; not yet opened in Power BI Desktop. Power BI Desktop runs only on Windows, and PBIP is a Microsoft preview feature.
